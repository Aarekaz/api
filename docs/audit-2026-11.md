# API audit, November 2026

Branch `audit-2026-11`, from `master` at e9cab7e. Baseline: `npx tsc --noEmit`
clean, `npx vitest run` 52 files / 663 tests passing.

The ground rules are the ones in AGENTS.md. Website routes keep their bodies
byte for byte (the freeze test is the check). App routes use `lib/http.ts`.
Migrations are additive.

Each finding below gives the evidence (file:line on `master`), the risk, the
fix and the effort (S under an hour, M an evening, L more). The ranking at the
end orders them by risk times reach, divided by effort. Items marked
**done** were fixed on this branch, and the commit list in the report says
where.

## 1. Duplicated logic

### 1.1 Website CRUD routes are the same file, copied seven times

`routes/experience.ts`, `education.ts`, `skills.ts`, `uses.ts`,
`projects.ts`, `posts.ts` and `photos.ts`, plus most of `shelf.ts`, each
re-implement the same handlers:

- List: `parseListQuery`, then a filter builder, then `parseSort`, then
  `SELECT * … LIMIT ? OFFSET ?`. For example `experience.ts:93-111`.
- Get one: `parseId`, then `"Invalid id"`, then the published filter, then
  `"X not found"` (`experience.ts:113-133`).
- Create and replace: `parseJson` plus `"Invalid JSON"`, then `validateBody`
  (`experience.ts:136-144`, `:172-180`). There are 46 copies of the
  `"Invalid JSON"` pair across 19 route files.
- PATCH: one `Object.prototype.hasOwnProperty.call(data, "col")` block per
  column, which is 102 blocks in all (experience 8, education 7, location 15,
  photos 13, projects 10, posts 7, shelf 33, skills 3, uses 5). See
  `experience.ts:205-244`.
- Delete: `parseId`, then `DELETE`, then the `changes === 0` check, then a 404.

Risk: a fix lands in one copy and not the others. That has already happened:
the bounds differ, posts has no published filter at all, and `media.ts:34`
returns the first Zod issue where the rest return `"Validation error"` with
`flatten()`.

Fix: put shared helpers in one module for the website's dialect
(`lib/site-http.ts`: `readBody`, `badId`, `notFound`) plus a PATCH builder
(`patchColumns` in `utils/query.ts`), and migrate the routes. The bodies stay
identical, and characterisation tests come first. Effort M. **Done** for the
body, id and patch helpers across all eight files. A generic CRUD factory was
not attempted, because each table's columns and transforms differ, and a
factory would hide the SQL that each file keeps readable.

### 1.2 Two validation approaches, three error helpers

- `utils/validation.ts` (`validateBody`, `validateQuery`) returns a
  `ValidationResult` with a ready-made website-shaped `Response`.
- `lib/http.ts` (`parse`, `body`) throws `HttpError` and replies in the app
  shape.
- `routes/site.ts:33-46` re-implements `fail` and `body` by hand, including a
  copy of `zodMessage`.
- `routes/journal.ts:246-264` writes the app error shape out literally six
  times instead of calling `fail()`.
- `utils/response.ts:12` (`errorResponse`) is a third way of building
  `{ error }`.

Risk: shapes drift, which is the bug class AGENTS.md exists to prevent.

Fix:
- One module per dialect. App routes use `lib/http.ts` only. Website routes
  use `lib/site-http.ts`, which absorbs `utils/validation.ts` and
  `errorResponse`.
- `site.ts` and `journal.ts` move onto `fail` / `failWith`.

Effort S. **Done.** ADR 0007.

### 1.3 Every app handler has its own try/catch

There are 56 handlers in `links.ts` (11), `recipes.ts` (12), `documents.ts`
(9), `journal.ts` (7), `highlights.ts` (4), `sections.ts` (4) and `site.ts`
(2). Each wraps its body in `try { … } catch (error) { return fail(c, error) }`,
and each file defines a one-line `fail` wrapper around `failWith`
(`links.ts:65`, `documents.ts:196`, `journal.ts:185`, `highlights.ts:106`,
`sections.ts:108`, `recipes.ts:99`).

Risk: noise, and a handler that forgets the wrapper returns Hono's text 500
instead of the JSON error shape.

Fix: `appErrors(app, "Links request")` in `lib/http.ts` registers
`app.onError(failWith)`. Hono applies a sub-app's `onError` to its own
routes when they are mounted (`hono-base.js` `route()`). Effort S. **Done**
for links, documents, highlights, sections, recipes, journal and site.

### 1.4 Day strings and local dates, done four ways

- The `/^\d{4}-\d{2}-\d{2}$/` regex is written out 15 times (links.ts ×5,
  state.ts, documents-core, visits, training, refresh, recipes, journal, and
  three schema files).
- `toISOString().slice(0, 10)` is inlined 10 times even though
  `utils/date.ts dateOnly` exists.
- "The calendar day of an instant in a zone or at an offset" has two
  implementations: `services/places.ts:39-50 localDate` (an offset, else New
  York) and `routes/journal.ts:196-206 dayIn` (a zone, else an offset).

Risk: the two local-day functions differ subtly. One uses `en-US`
`formatToParts`, the other `en-CA` `format`. A third copy would pick one at
random.

Fix: `utils/date.ts` gets `DAY`, `isDay`, `daySchema`, `dayInZone(zone)` and
`dayAtOffset(at, minutes)`, and the callers use them. Effort S. **Done.**
ADR 0008.

### 1.5 Pagination: three limit parsers, one of them unsafe

- `lib/http.ts:136 limitFrom` is correct: it floors, takes at least 1 and
  applies a cap.
- `utils/query.ts:27 parseListQuery` has no floor and no lower bound
  (see 7.1).
- `routes/location.ts:138` has its own copy of the same bug.
- `routes/documents.ts:201` and `:291` hand-roll the clamp again.

Fix: one `clampLimit(raw, fallback, max)` in `utils/query.ts`, used by
`limitFrom`, `parseListQuery`, location and documents. Effort S. **Done.**

The two list shapes stay: website lists are bare arrays with
`limit`/`offset`, and app lists use `{ items, next_cursor }`. Merging them
would change the website.

### 1.6 ETag / data_versions

Only Places uses `notModified` and `data_versions` (`routes/visits.ts`).
Nothing is duplicated; the gap is reach. Other expensive reads (wrapped,
training bests, links stats) have no conditional GET. That is under section 8,
not duplication.

### 1.7 R2 access

The R2 code is not duplicated, but it is inconsistent:
- Photos and blog images both put to `R2_BUCKET` with their own copies of the
  presign/HMAC code (`photos.ts:40-110`, `blog-images.ts:30-128`). That is
  about 70 lines in near-identical pairs.
- The journal falls back from `R2_PRIVATE` to `R2_BUCKET` (`journal.ts:256`).

Fix: one `services/upload-token.ts` for sign and verify. Effort S. **Done**,
with part of 7.4.

### 2.1 The global error handler never runs

`index.ts:65` installs `middleware/error-handler.ts`, a try/catch around
`next()`. Hono's `compose` catches a thrown handler error at the handler's own
dispatch level and passes it to the app's `errorHandler` (the default:
`console.error` plus `text("Internal Server Error", 500)`). The middleware's
`await next()` therefore returns normally, so its JSON body with `requestId`
is never sent. `ApiError` is never thrown anywhere.

Risk: readers believe uncaught errors get a JSON body with a request id.
They get text.

Fix: delete the middleware and `ApiError`, keep today's behaviour (the
default handler), and pin it with a test. Making website 500s JSON is a
visible change, so it is listed for the owner. Effort S. **Done.**

## 4. Inconsistent patterns

### 4.1 Response envelopes

| Area | Success body | Error body | Create/update |
| --- | --- | --- | --- |
| Website CRUD | bare row or array | `{ error: string, details? }` | `{ ok: true, created_at }` 201, `{ ok: true, updated_at }`; 79 `ok: true` replies |
| App routes | the resource, lists `{ items, next_cursor }` | `{ error: { code, message, details? } }` | the resource |
| vault, media, refresh, whoop, spotify, app-auth, status | ad hoc | `{ error: string }` | ad hoc |

This is deliberate for the website (AGENTS.md). Vault, media and the
integrations are app-only, but their error bodies are the website's. Moving
them to the app shape changes what the app parses, so it is an owner decision
(section 11).

### 4.2 Status codes

- A bad bearer scheme and an unknown token are both **403**
  (`middleware/auth.ts:33,46`). By HTTP semantics they are 401. The apps may
  branch on 403, so this is listed, not changed.
- `journal.ts:246`: 415 with code `invalid` while `codeFor(415)` is
  `unsupported`. Kept as is (it is the app's contract) and pinned by a test.
- `vault.ts:136` sends 400 for an over-long batch where the others send 413.
  Minor.

### 4.3 Validation libraries

Zod is used throughout, but:
- `training.ts:336-380` and `documents.ts:237-300` cast `parseJson` results
  to `Record<string, unknown>` and check fields by hand.
- `vault.ts:132-184` does the same.

Not unsafe (every field is checked), but it is a second style. Effort S each.
Left.

### 4.4 Naming

- Files mix `routes/whoop-health.ts` (factory `createWhoopHealthRoute`) with
  default-exported apps.
- `utils/` and `lib/` overlap in purpose: `lib/` is "shared request helpers"
  and `utils/` is "pure helpers". This branch puts new request helpers in
  `lib/` and keeps `utils/` pure. ADR 0007 states it.

## 7. Security

### 7.1 `?limit=-1` removes the LIMIT

`utils/query.ts:27`: `Math.min(Number("-1") || 100, 1000)` is -1, and
SQLite's `LIMIT -1` means no limit. `?limit=1.5` binds a REAL and fails with
a datatype mismatch (a 500).

This affects projects, posts, photos, shelf, shelf/diary, education,
experience, skills and uses. Most of these are callable with SITE_TOKEN.
`location.ts:138` (cap 10,000) and `documents.ts:291` (search) have the same
bug.

No client sends a negative or fractional limit: the website clamps to
1..1000 (`anurag.me/lib/api.ts getShelf`), and the apps send integers.

Fix: floor, and fall back to the default when the value is below 1; clamp
`offset` at 0 (already done). Effort S. **Done.**

### 7.2 SITE_TOKEN can read the WHOOP profile

`lib/site-reads.ts:14`, `/^\/v1\/health\/whoop\/[a-z-]+(\/[\w-]+)?$/`,
matches `/v1/health/whoop/profile`. That route returns name, email, height,
weight and max heart rate (`whoop-health.ts:205-217`). The website reads only
`workouts` and `cycles` (`anurag.me/lib/whoop.ts:6`). The site-token test
also covers `sleeps` and `overview`.

Fix: an explicit list,
`(overview|cycles|recoveries|sleeps|workouts)(/id)?`. Effort S. **Done.**

### 7.3 SITE_TOKEN can read unpublished content

`utils/query.ts:82-92`: `?include_unpublished=true` turns off the published
filter for whoever asks. Its comment ("the public site and the OS
authenticate with the same token") is stale since ADR 0004. The website never
sends the parameter.

Fix: a SITE_TOKEN request that carries `include_unpublished` is refused (403,
the website's error body). Effort S. **Done.**

`GET /v1/posts` has no published filter for anyone (`posts.ts:93-120`), so
the site token sees drafts. The website filters them itself. Adding the
filter for site callers changes the website's data, so it is listed for the
owner (section 11).

### 7.4 Presigned uploads

`photos.ts:316-339`, `blog-images.ts:151-177`:
- No size cap on the PUT.
- Photos accept any `image/*`, including `image/svg+xml`, which is script on
  the public media domain.
- A token can be reused for 5 minutes, and photo and blog tokens are
  interchangeable.
- A malformed token throws inside `atob` / `JSON.parse` and returns a 500
  instead of a 403.
- `API_TOKEN` doubles as the HMAC key.

Fix: a shared `upload-token.ts` with a purpose in the payload, try/catch to a
403, the blog type allow-list for photos, and a Content-Length cap. Effort S–M.

**Partly done.** Malformed tokens now get a 403, and each route accepts only
keys under its own prefix (`photos/`, `blog/`); tests cover both.

Still left:
- Rejecting SVG changes what the app can upload, so it needs the owner's call.
- The size cap.
- Single-use tokens.
- A separate signing secret, which needs a new secret.

### 7.5 Device sessions never expire

`services/app-auth.ts:77-110`:
- There is no `expires_at` and no revoke-all.
- The per-isolate cache keeps a revoked token working for up to 5 minutes.
- The state is 8 characters.

The token is stored hashed and is 285 bits (fine).

Fix: an additive `expires_at`, a sliding window, and an owner revoke-all.
Effort M. Left: it changes when the apps must sign in again, which is the
owner's call.

### 7.6 Public writes without bounds

- `GET /auth/app/github/start` inserts an `app_oauth_states` row per call,
  and nothing deletes them.
- `POST /v1/crowd` takes any `id` with no length cap and no rate limit
  (`crowd.ts:60-89`).

Fix: a Cloudflare rate-limit rule (dashboard, owner), a cron sweep of expired
states (a data write, so not tonight), and an `id` length cap. Effort S.
Left (listed).

### 7.7 Bodies are unbounded

- Most string and array fields in `schemas/content.ts` have no `.max()`.
- There is no `bodyLimit`.
- The WHOOP webhook reads the whole body before it checks the signature.

All callers are the owner, except the webhook and crowd. Fix: `hono/body-limit`
on the webhook and crowd first. Effort M. Left.

### 7.8 Raw error messages reach clients

`refresh.ts:47,66,98`, `media.ts:51,76` and `shelf.ts:625` return
`error.message`, which can carry upstream or SQL text. Owner-only routes, so
Low. Left: the message is part of what the app shows.

### Confirmed fine

- Every `/v1/*` route is behind `requireAuth`. The exceptions are the listed
  presign paths (HMAC) and crowd.
- The integrations mounted at `/` put their owner actions under `/v1`; the
  callbacks verify single-use hashed state, and the webhook verifies an HMAC
  over timestamp and body with a ±5 minute window and trace-id replay dedup.
- Bearer compares run in constant time over SHA-256 digests.
- Sort columns come from allow-lists; every value is bound.
- R2 keys are generated by the server; journal and vault paths are checked.
- CORS `*` only on the presign and crowd paths, with no credentials.
- The request logger records method and path only.

## 10a. Also on this branch: reading time

This was not part of the audit; the owner reported it the same night.
`saveProgress` credited time read as progress gained times `reading_minutes`,
which is often far too low, and it never counted re-reading.

`PUT` (and now `POST`) `/v1/links/:id/progress` take optional `seconds`,
`words` and `report_id`:
- `seconds` is credited, clamped to the wall-clock time since the previous
  progress plus 30 s, with a cap of 10 minutes per report. It counts even
  when progress doesn't move or the write loses last-write-wins.
- `report_id` dedupes a report through `reading_reports` (migration 0051, not
  applied remotely; the code works without it).
- `words` raises `reading_minutes`.
- Without `seconds`, the old formula still applies.

The reply shape is unchanged. See ADR 0006.

## 11. Needs the owner

- **Website 500 bodies.** Uncaught errors return text
  `Internal Server Error`. Making them JSON (`{ "error": "…" }`) is a visible
  change to the site's error path.
- **Drafts in `GET /v1/posts`** are visible to anyone with a token, the site
  token included. Should the site token get only published posts?
- **SVG uploads to photos**: reject them (stored XSS on media.anuragd.me)?
- **Device session expiry** and a revoke-all endpoint.
- **401 vs 403** for a bad or unknown token. The apps may depend on 403.
- **Vault, media and integration routes**: move them to the app error shape?
  The app parses these bodies.
- **Lockfiles**: npm or pnpm.
- **Wrangler upgrade** (4.82.2 → current) before any `compatibility_date` bump.
- **LEGACY_LIST_KEYS**: it is "off", so ADR 0005's end state has arrived.
  Deleting the flag and code removes the switch back; keep it or delete it?
- Apply `migrations/0051_reading_reports.sql` and
  `migrations/0052_list_indexes.sql` remotely when deploying. Both are
  additive, and the code works without them.
